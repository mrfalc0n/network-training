# network-training

Hands-on data center fabric lab — containerlab, Arista EOS, SONiC/FRR, Ansible.

Built by **Chris Collins** ([mrfalc0n](https://github.com/mrfalc0n)) as a working lab
environment for AI-infrastructure networking: leaf-spine underlays, BGP-EVPN/VXLAN
overlays, and the RoCEv2 config surface (PFC, ECN/WRED, DSCP-to-queue, ECMP entropy).

Curriculum follows the **Arista ACE Specialist – Data Center** blueprint
(AN-DC-EN01 engineering + AN-DC-OP01 operations), plus the Arista Automation track.
Everything here is reproducible from source: `clab deploy` and it exists.

## Environment

WSL2 on Windows, with **Docker Engine installed natively inside the Ubuntu distro** — not
Docker Desktop's WSL integration. containerlab manipulates network namespaces and veth
pairs directly, and every upstream document assumes the daemon and your shell live in the
same distro. Repos live in the Linux filesystem, never under `/mnt/c`.

```bash
cd ~/life-os/repos
git clone https://github.com/mrfalc0n/network-training.git
cd network-training
chmod +x scripts/*.sh
./scripts/check-env.sh          # reports what is missing before you install anything
```

Read [`docs/00-environment-setup.md`](docs/00-environment-setup.md) start to finish before
typing anything else — it assumes no prior Docker or containerlab experience and labels
every step with whether it happens on Windows or in the WSL terminal.

## Conventions used throughout

- **No hand-configuring past Phase 2.** From Phase 3 forward every device config is
  generated by Ansible + Jinja. If a lab can't be rebuilt from an empty directory
  with one command, it isn't finished.
- **Verify, then claim.** Every concept has a verification command and an expected
  output recorded in `docs/`. "It came up" is not evidence.
- **Whiteboard cold, then configure.** Each phase has a self-check list in
  `docs/whiteboard/`. If it can't be drawn from memory, it isn't learned.
